# 4.1 改造路径（brownfield · React/Next.js）

> page-template-gen 4.1 路径详细规范。何时 Read：[TECH_FE] `模式: brownfield` 时；mixed 中分发到 brownfield 子页面时。

## 目标

对已有项目做外科手术：
- **§4.2 新建文件** → TSX 骨架（结构 + 样式写实，逻辑层 `// TODO step5` 占位）
- **§4.3 改动现有文件** → 按插入点描述定位，每处独立 `Edit`：import 行 / 组件注入 / 移除目标段，不触碰无关代码

## 读取顺序

### 步骤 0 — 建工作清单

读 [TECH_FE]，提取：
- §4.0 现有足迹基线（brownfield 模式必读）：每个被改文件的 组件库引用 / 埋点 / i18n key / 业务过滤 / 响应式策略 / dark mode 清单
- §4.2 新建清单：路径 / 职责 / 来源编号
- §4.3 改动清单：路径 / 改动类型 / 插入点描述 / 来源编号
- §4.4 删除清单
- §4.6 足迹删除授权清单（brownfield 模式必读）：哪些足迹被授权删除
- §9 探测结果（含精确行号 / props 形状 / 暗坑，**直接取用，不重复 grep**）

> **brownfield 硬规则（足迹保留）**：写代码时，§4.0 列出但 §4.6 未登记的足迹**必须保留**——组件库组件继续 import、埋点调用继续保留、i18n key 优先复用 §4.0 已有 key、业务过滤逻辑原样保留、响应式策略沿用同一套（CSS-breakpoint 不切换为 JS-detect、反之亦然）、暗色模式 class 必须在新代码上等价覆盖。
> 如果实现时发现某条足迹无法继承，**停下回报**，不要静默删除。需要授权删除的回 step 3 补 §4.6。

### 步骤 1 — 读取设计 token 与组件清单

读 [MANIFEST]，取每个组件的 `status` + `design_tokens` + `placement` + `wraps`：
- `status: 不存在，需新建` → 按骨架格式新建
- `status: 内联复用` → 不新建独立文件，按 `inline_usage` 字段在调用方内联
- `status: 复用现有` 或 `已有可复用` → 不新建，直接用 `import_from` 路径
- `status: 已有需改造` 或 `同功能已有` → 评估是否复用，不能复用再新建
- `figma_node_missing` → 跳过 design token，用 tech-fe.md §5 方案描述
- `status: 待 step 3 确认` → **fail-fast**：报错并中止，错误信息 `"upstream Phase 2 未完成 status 升级；component=<name>，请回 step 3 重跑 tech-solution-generator Phase 2"`
- 任何**不在上表的未知 status 值** → **fail-fast**：报错并中止，附"合法 status 全集见 pageforge/SKILL.md §[MANIFEST] status 受控集合；建议默认值：不存在，需新建"。**禁止静默落到 default 分支**

从 [MANIFEST] 的 `design_tokens` 字段照抄数值，转 Tailwind class：

| Figma 字段值示例 | Tailwind 转换规则 |
|---|---|
| `border_radius: 8px` | `rounded-lg` |
| `padding: 8px 12px` | `py-2 px-3` |
| `text_font: Roboto 12px` | `text-xs` |
| `text_color: #000000` | `text-[#000000]`（一律用任意值语法，与 Figma 原值一一对应）|
| `background: #ffffff` | `bg-[#ffffff]`（同上）|
| `shadow: 0px 6px 16px rgba(0,0,0,0.36)` | `shadow-[0px_6px_16px_rgba(0,0,0,0.36)]` |

**照抄 Figma 值，不估算，不替换等价 token（strict equality only — 不允许把 `#1a1a1a` 近似映射成 `bg-gray-900` 等）。**

读 [CODE_BASELINE] M4 确认所有 import 路径（不猜路径）。

### 步骤 2 — 生成新建文件（§4.2 逐条）【4-B component-skeleton 阶段】

> 本步骤对应阶段总览中的 4-B。**按 NW-* loop 单次单文件**处理，禁止单次产多个 NW-*；每个 NW-* 处理结束（无论成功失败）追加一行到 [TEMPLATE_SUMMARY] nw_components 状态表（schema 见上方"通用规则"节）；单条失败按 partial success fallback 处理，**不抛主流程**。

对每个新建文件，生成 TSX 骨架并 `Write` 到指定路径：

```tsx
// [GENERATED by step 4.1 page-template-gen]
// Step 5 需实现：
//   - [逻辑项 1，来自 tech-fe.md §5.x]
//   - [逻辑项 2]

import React from 'react';
import { ExistingComponent } from '<IMPORT_ALIAS>/components/...';  // <IMPORT_ALIAS> 与具体路径来自 code-baseline M2/M4，不假设 `@/`
// TODO step5: 补充 hook imports

interface Props {
  // TODO step5: 按 tech-fe.md §5.x 补充 props
}

export function ComponentName({}: Props) {
  // TODO step5: hook 调用逻辑

  return (
    <div className="[Figma token → Tailwind]">
      {/* TODO step5: 子组件逻辑 */}
    </div>
  );
}
```

> `<IMPORT_ALIAS>` 必须读 [CODE_BASELINE]：先看 M2 是否记录 alias 配置（如 tsconfig paths / jsconfig），再看 M4 组件条目实际 import 路径形式。Next.js / Vite 常见 `@/`，但其他框架（CRA / RN）可能用相对路径或不同 alias，**不假设默认值**。

Bash 校验：`ls {§4.2 中每个路径}` — Write 的文件数必须等于 §4.2 条目数；数量不符则报错并停止，不进入步骤 3。

### 步骤 3 — 改动现有文件（§4.3 逐条）【4-C 收尾 aggregator 阶段（brownfield）】

> 本步骤对应阶段总览中的 4-C：在 brownfield 模式下，"组件注入"等价于 greenfield 4-C 的"替换 placeholder div"——目标是把步骤 2 产出的 status=`ok` 的 NW-*.tsx import 到既有文件并 JSX 注入。status=`skeleton-failed` 的 NW-* 在既有文件中保留 `{/* TODO step4-retry: <nw_id> */}` 注释占位，不强行注入。

> **'use client' OR 聚合**：brownfield 改造的既有文件大多已有 'use client' 标记或不需要（取决于位置）；新引入的 NW-* `is_client` 不影响既有文件 'use client' 状态——除非 nw_components 中有 is_client=true 的 NW-* 注入到一个**目前未标 'use client' 的 RSC 文件**，此时需要在 §4.3 改动条目里**显式加 'use client'**；该判定由 4-C 步骤完成而非步骤 2。

对每个改动文件：

1. `Read` 读完整文件
2. 对照 §4.3 + §9 行号定位插入点（§9 没有的再 Bash grep）
3. `Edit` 精确修改：
   - import 加在文件顶部 import 块末尾
   - 组件注入带 Tailwind class + `md:hidden`（按需）
   - 移除段加注释说明迁移目标：
     ```tsx
     {/* [REMOVED by step 4.1: IM-007 autoplay toggle 已迁至 ChatHeader] */}
     ```

### 步骤 3.5 — 执行删除清单（§4.4）

对步骤 0 读到的每条删除记录：

1. `ls {路径} 2>/dev/null && echo EXISTS || echo SKIP` — 确认文件仍存在
2. 存在 → `Bash rm {路径}`；不存在 → 记录"已不存在，跳过"
3. 若删除文件有 import 被其他文件引用，`Grep` 反查，**不自动改引用文件**，在产物摘要里标注"⚠️ 需人工清理遗留 import"

```markdown
对 nw_components.status=`skeleton-failed` 的 NW-*：手动重跑 step 4-B + step 5-B 单 NW-*，重跑成功后改 status=`ok`，再重跑一次 step 4-C 收尾 + step 5-C postcondition。
```
