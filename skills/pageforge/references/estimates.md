# §E 各步预估耗时

下表用于排期与瓶颈定位。耗时随项目规模 / NW-* 数量 / 用户应答速度浮动；`实测` = 已有运行数据校准，`估算` = 无实测数据的保守估计。

| Step | 预估耗时 | 来源 | 主瓶颈 |
|---|---|---|---|
| 0 项目盘点 + PRD/API 采集 | ~5-12 min（双 agent 并行，取较慢者） | 估算 | baseline grep 量随仓库规模；PRD/API 远端文档拉取 |
| 0.5 PRD scope-narrower | ~1-3 min（仅超阈值时触发，含 1 次用户应答） | 估算 | 等用户选 scope |
| 1 澄清文档生成 | ~5-10 min 生成 + 用户应答时长（不可控） | 估算 | 等用户逐条回答待澄清项 |
| 2 视觉分析 | 2.B ~7 min / 2.C ~14 min / 2.A ~35 min | 实测校准（见 SKILL.md §P step 2 模板） | figma MCP 拉取量 × mode 档位 |
| 3 技术方案 + 实现层探测 | ~8-15 min | 估算 | footprint 提取 + §9 Q-T* grep 探测 |
| 4 模板 + 骨架 | 4-A ~3-5 min ＋ 4-B（NW-* 数 ×〔~11 min 生成 ＋ ~10 min verify〕**÷ K 并发槽**，§B.8）＋ 4-C ~3-5 min | 4-B Run 3 实测校准（§B.1）；4-A/4-C 估算 | NW-* 总数 / K |
| 5 逻辑填充 | 5-A ~5-8 min ＋ 5-B（NW-* 数 ×〔~10-12 min 填充 ＋ ~10 min verify〕**÷ K 并发槽**，§B.8）＋ 5-C ~2 min | 5-B 实测校准（§B.1）；5-A/5-C 估算 | NW-* 总数 / K × TODO 密度 |
| 5.5 figma-review | ~5-15 min（按需；NW-* ≤ 5 可跳过） | 估算 | NW-* 数量 |

- 各 step 之间严格串行；step 0 内部双 agent、step 4-B/5-B 内部 K 并发槽（§B.8）是并行点。总耗时 ≈ 各步之和，其中 4-B/5-B 取「NW-* 数 × 单 NW-* 闭环 ÷ K」。
- **最大不确定项**：step 1 的用户应答时长、step 2 的 figma MCP 拉取、step 4/5 的 NW-* 总数与并发度 K。排期时按 NW-* 数量 ÷ K 先估 4-B/5-B，其余步骤取上界。
- 实测窗口变化时同步修订本表与 §B.1，不要在 agent prompt 里写死耗时。
